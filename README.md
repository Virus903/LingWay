# LingWay — английский для путешествий

Веб-приложение для подготовки к поездке: короткие тематические уроки, диалоги,
разговорник, повторение слов и персональный учебный маршрут. Ученики занимаются
самостоятельно или в группе; преподаватели назначают обучение и анализируют
результаты; администраторы управляют пользователями и учебным контентом.

Проект включает сервер на C#, SQL Server и браузерный интерфейс с отдельными
Razor-файлами экранов, светлой/тёмной темами и поддержкой офлайн-обучения.

## Возможности

### Ученик

- Регистрация, подтверждение электронной почты, вход, восстановление пароля.
- Гостевое обучение с переносом прогресса в постоянный аккаунт.
- Настройка цели, даты поездки, уровня и ежедневного времени занятий.
- «Мой день»: статистика, следующий урок, план подготовки и загрузка пакета.
- Семь модулей: аэропорт, самолёт, отель, кафе, город и транспорт, магазин,
  экстренные ситуации. В поставке 21 урок и 375 фраз разговорника.
- Последовательное открытие модулей; экстренные ситуации доступны постоянно.
- Карточки слов с переводом, транскрипцией и иллюстрациями; выбор ответа,
  сборка фразы, пропуски, диктант, аудирование, повтор за диктором и диалоги.
- Диалоги с вариантами продолжения и несколькими репликами на маршруте.
- Поэтапные подсказки, повторные попытки, баллы и звёзды.
- Сохранение незаконченного урока, результаты и работа над ошибками.
- Личный словарь, ручное добавление фраз, избранное, недавние фразы и повторение.
- Паспорт путешественника, штампы, достижения и серия занятий.
- Профиль с аватаром, настройки темы, скорости речи и напоминаний.
- Центр уведомлений в колокольчике: прочтение, напоминания и назначения.
- Выгрузка собственных данных и удаление аккаунта.

### Преподаватель

- Создание и ведение своих групп, добавление участников.
- Назначения всей группе или отдельному ученику, сроки выполнения.
- Реестр: «не назначен», «назначен», «в процессе», «пройден»,
  «нужно повторить»; просрочка показывается отдельно.
- Результаты, трудные фразы, фильтры по группе, ученику, модулю, уровню,
  датам и сроку назначения; выгрузка CSV/XLSX.
- Сервер ограничивает доступ группами данного преподавателя.

### Администратор

- Обзор системы, управление пользователями, ролями и группами.
- Редактор урока: задания, словарь, критерии оценивания и версии.
- Медиатека аудио/изображений с поиском и повторным использованием файлов.
- Проверка обязательных данных, вариантов ответа, переходов и медиа перед
  публикацией уроков и пакетов контента.
- Импорт фраз и учеников с предпросмотром, проверкой полей и дубликатов.
- Журнал действий, общие отчёты и техническая проверка качества уроков.

## Стек и архитектура

| Область | Реализация |
| --- | --- |
| Среда разработки | Visual Studio 2026, нагрузка «ASP.NET и веб-разработка» |
| Платформа | .NET 10; версия SDK закреплена в `global.json` |
| Сервер | ASP.NET Core MVC и API-контроллеры, C# |
| Интерфейс | Razor `.cshtml`, HTML, CSS, JavaScript |
| Данные | SQL Server, Entity Framework Core 10 |
| Аккаунты | ASP.NET Core Identity, роли Student / Teacher / Admin |
| Табличный обмен | CSV, XLSX / ClosedXML |
| Офлайн | Service Worker, Cache Storage, IndexedDB |
| Проверки | xUnit, Playwright, сценарии PowerShell |
| Почта | SMTP; локальный режим только для разработки |
| Голос | Браузерные API, сохранённое синтетическое аудио, адаптер Azure Speech |

Приложение представляет собой один серверный проект. Контроллеры принимают
запросы и проверяют права, сервисы выполняют бизнес-логику, EF Core работает
с SQL Server. `LingWayDbContext` описывает предметную модель, `IdentityContext`
обслуживает Identity; операции создания аккаунтов и импорта согласуют транзакции.

Интерфейс **гибридный**: Razor собирает каталог HTML-шаблонов, JavaScript
подставляет данные и переключает экраны по hash-маршрутам. Разметка экранов
разделена по `.cshtml`, но каждому экрану не соответствует отдельный MVC action
с `@model`. Этот подход позволяет использовать учебный интерфейс без сети.
Маркеры шаблонов обрабатывает `razor-templates.js`; сервер остаётся источником
прав доступа и итоговой проверки результатов.

## Запуск

### Требования

- Windows, Visual Studio 2026 или .NET SDK 10 (см. `global.json`).
- Локальный SQL Server с поддержкой JSON-функций и SSMS для выполнения SQL.
- Edge/Chrome для основных браузерных сценариев.
- Node.js и npm нужны для браузерных тестов, но не для запуска сервера.
- Установленный английский голос Windows нужен для генерации офлайн-аудио.

### 1. Создать новую базу

Откройте **`Database/LingWay.sql`** в SSMS и выполните весь
файл кнопкой «Выполнить» (F5). Режим SQLCMD не нужен. Он создаёт базу
**LingWay**, все таблицы, роли, представления и учебное наполнение.
Если база LingWay уже существует, установка пропускается без её изменения.

Скрипт предназначен для новой базы. Он содержит структуру и учебный контент:
7 модулей, 21 урок с актуальной версией, 375 фраз и каталог достижений.
Аккаунты, личные результаты, готовые офлайн-пакеты и архивные редакции в
начальную установку не входят. Пакеты публикуются администратором после
подготовки аудио. Изменения существующей БД требуют отдельной миграции и резервной копии.

### 2. Настроить подключение

По умолчанию используется Windows Authentication:

```text
Server=localhost;Database=LingWay;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True
```

Для другого сервера задайте `ConnectionStrings:LingWay` через User Secrets,
переменную `ConnectionStrings__LingWay` или исключённый из Git файл
`src/LingWay.Web/appsettings.Local.json`. `TrustServerCertificate=True` —
настройка локальной разработки, не рекомендация для публичного сервера.

### 3. Настроить почту

Публичная конфигурация не содержит адреса отправителя и пароля. Для Gmail:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/configure-mail.ps1
```

Скрипт запросит адрес и пароль приложения Google в скрытом поле и сохранит их
в .NET User Secrets вне репозитория. Для другого SMTP задайте `Mail:Host`,
`Mail:Port`, `Mail:From`, `Mail:User`, `Mail:Password`, `Mail:Mode=Smtp`.
Не используйте обычный пароль почты вместо пароля приложения.

Для локального стенда без доставки писем:

```powershell
dotnet user-secrets set "Mail:Mode" "Local" --project src/LingWay.Web
```

Этот режим допускается только в Development. Коды записываются в
`src/LingWay.Web/App_Data/mailbox.txt`; файл запрещено публиковать.
Чтобы вернуться к SMTP, задайте `Mail:Mode=Smtp` и перезапустите сервер.

### 4. Собрать и запустить

```powershell
dotnet restore LingWay.sln
dotnet build LingWay.sln
dotnet run --project src/LingWay.Web --launch-profile https
```

HTTPS: `https://localhost:7110`; HTTP-профиль: `http://localhost:5180`.
Для HTTPS при необходимости выполните `dotnet dev-certs https --trust`.
В Visual Studio откройте `LingWay.sln`, выберите `LingWay.Web` и нажмите Ctrl+F5.
Альтернативный локальный запуск — `START.bat`.

### 5. Создать первого администратора

Готовых аккаунтов с общедоступными паролями нет. Зарегистрируйте и подтвердите
свой аккаунт. В SSMS на своей новой базе выполните следующий запрос, заменив
пример адреса на адрес созданного пользователя:

```sql
DECLARE @Email nvarchar(256) = N'owner@example.com';
DECLARE @UserId uniqueidentifier =
    (SELECT Id FROM dbo.AspNetUsers WHERE NormalizedEmail = UPPER(@Email));
IF @UserId IS NULL THROW 51030, 'Register the account first.', 1;
BEGIN TRANSACTION;
DELETE FROM dbo.AspNetUserRoles WHERE UserId = @UserId;
INSERT dbo.AspNetUserRoles(UserId, RoleId)
SELECT @UserId, Id FROM dbo.AspNetRoles WHERE NormalizedName = 'ADMIN';
UPDATE dbo.AspNetUsers SET SecurityStamp = CONVERT(nvarchar(36), NEWID())
WHERE Id = @UserId;
COMMIT;
```

Выйдите и войдите заново. Остальные роли назначаются через кабинет
администратора. Запрос предназначен владельцу БД, а не обычным пользователям.

### 6. Подготовить офлайн-аудио

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-offline-audio.ps1
```

Затем опубликуйте пакет в административном интерфейсе. Ученик скачивает его
на странице «Мой день». Генератор использует установленный английский голос
Windows; готовые локальные WAV-файлы и пользовательские загрузки в Git не входят.

## База данных

EF Core отображает существующую SQL-схему; изменения схемы хранятся в SQL-файлах.
Приложение не вызывает автоматическое удаление или пересоздание БД при запуске.
Установочный файл — `Database/LingWay.sql`. Он включает создание таблиц,
ограничений, индексов, ролей, представлений и начальное учебное наполнение.

Основные связи: пользователь → профиль/результаты/словарь; модуль → уроки →
неизменяемые версии; попытка → ответы и конкретная версия урока; преподаватель →
группы → участники и назначения. Индивидуальное назначение дополнительно
ссылается на ученика. Каталоги фраз и достижений отделены от личных данных.

`StepsJson` и `MetadataJson` содержат задания, ветки, словарь и критерии,
**не HTML страниц**. Вёрстка хранится в `Views`, поведение — в JavaScript.
Служебные таблицы импорта не используются как источник экранов.

## Дизайн

Светлая тема использует тёплый светлый фон, тёмно-синий текст и бирюзовые
акценты. Тёмная тема — глубокий тёмный фон, светлый текст и контрастные акценты.
Состояние ошибки не обозначается одним цветом: используется текстовая обратная связь.

| Токен | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Фон `--paper` | `#F7F4EC` | `#090F18` |
| Поверхность `--white` | `#FFFEFA` | `#101925` |
| Текст `--ink` | `#17324D` | `#EEF4F8` |
| Вторичный текст `--muted` | `#687B8E` | `#A2B3C6` |
| Акцент `--teal` | `#2D9C8C` | `#67CBBF` |
| Граница `--line` | `#D9E1E5` | `#29364A` |

Значения приведены по базовым CSS-токенам; отдельные компоненты имеют свои
состояния и оттенки. Логотип представлен SVG для двух тем. Навигационные
иконки выполнены в контурном SVG-стиле: дом, маршрут, книга, повторение,
профиль, замок, настройки, уведомления. Иллюстрации ситуаций создаются в SVG.
Интерфейс адаптируется под узкие экраны; проверялась ширина 390 px.

## Правила обучения

- Нормализация текста учитывает регистр, пунктуацию, пробелы и ряд сокращений.
- Точное совпадение даёт полный балл, близкое написание — половину.
  Для нечёткого сравнения учитываются заданные ключевые слова, отрицания
  и порядок чисел. Это не универсальная семантическая оценка языка.
- Повторный ответ уменьшает кредит; допускается не более трёх попыток.
- Подсказки идут по ступеням; использование подсказки влияет на звёзды.
- Карточки ознакомления со словами не входят в знаменатель оценки.
- Порог прохождения хранится в критериях версии урока. Три звезды требуют
  не менее `max(90, порог прохождения)` без подсказок и повторов; две —
  прохождения; одна — результата от 50%, если урок не пройден.
- Попытка закреплена за версией урока. Старые результаты не пересчитываются
  по критериям нового содержания.

## Офлайн и синхронизация

Ученик заранее скачивает пакет при работающем сервере. В него входят уроки,
разговорник и подготовленные медиа. Оболочка кэшируется Service Worker,
контент и очередь результатов хранятся в IndexedDB с разделением по аккаунтам.

Файлы адресуются по SHA-256. Обновление скачивает необходимые файлы, проверяет
целостность и переключает пакет только после завершения. При обрыве остаётся
предыдущая рабочая версия. Размер показывается перед загрузкой.

Результаты отправляются партиями до 50 записей. UUID и хеш содержимого
защищают от дублей; сервер проверяет владельца. Незаконченный урок сохраняется
отдельно. Вход, администрирование и внешняя оценка произношения требуют сети.
Браузер может очистить локальные данные: офлайн-хранилище не заменяет резервную копию.

Для проверки отключите соединение с сервером через DevTools Offline,
обновите уже закэшированную страницу, пройдите скачанный урок, восстановите
сеть и проверьте результат. Отключение Wi-Fi само по себе не отключает `localhost`.

```powershell
dotnet test tests/LingWay.Tests/LingWay.Tests.csproj
cd tests
npm install

node api.cjs
```

Браузерные/API-тесты требуют **отдельного подготовленного стенда на порту 5181**,
тестовой БД, учебных данных и ролей. Некоторые сценарии используют установленный
Edge и Windows/SQL Server. Не запускайте изменяющие данные тесты на рабочей базе.
Сами команды не создают автоматически полный тестовый стенд.

Учётные данные тестовых пользователей задаются файлом `tests/accounts.local.txt`
либо переменной `LINGWAY_TEST_ACCOUNTS` с абсолютным путём. Формат:

```text
Email: admin@lingway.local
Пароль: <ваш тестовый пароль>
Email: teacher@lingway.local
Пароль: <ваш тестовый пароль>
Email: student@lingway.local
Пароль: <ваш тестовый пароль>
```

Создайте эти аккаунты только на изолированном стенде. Файл исключён из Git.
`PLAYWRIGHT_MODULE` позволяет указать установленный модуль Playwright;
обычный вариант — `npm install` в `tests`.

Зафиксированный проверочный прогон: 39 xUnit-тестов, 45 проверок учебного
качества, 40 API-проверок, 14 проверок офлайн/синхронизации. Это результат
локальных прогонов, а не заявление о независимой сертификации.
Контентный xUnit-тест использует `tests/fixtures/learning-content.json`, который
включён в репозиторий и копируется в тестовую сборку. Проверка уроков обязательна
и не требует подключения к SQL Server. После редакции курса fixture можно
обновить через `scripts/export-learning-content.ps1` и проверить diff до коммита.

Проверка публичной схемы и seed на временной БД:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-public-database.ps1
```

Нужны права создания/удаления тестовой БД на локальном SQL Server. Скрипт
создаёт уникальную временную БД, применяет SQL, проверяет состав и CHECKDB,
затем удаляет только свою тестовую базу.

## Безопасность и эксплуатация

- Identity, хеширование паролей, HttpOnly cookies, CSRF, блокировка входа,
  ограничение частоты запросов и серверные проверки ролей/принадлежности.
- Ключи SMTP/Azure не передаются клиенту и не хранятся в репозитории.
  User Secrets — локальный механизм разработки, не зашифрованный production vault.
- Внутренние уведомления сохраняются на сайте. Системные push-уведомления
  не являются активным пользовательским сценарием; остаточный код совместимости
  не означает проверенную фоновую доставку при закрытом браузере.
- Резервирование: `scripts/backup-database.ps1`, CHECKSUM, VERIFYONLY,
  проверочное восстановление и CHECKDB; локальная политика хранения — 30 дней.
- Удаление аккаунта очищает связанные данные и оставляет минимальный журнал
  удаления. При восстановлении старого backup нужно повторно применить
  `scripts/reapply-deletions.ps1` к изолированной восстановленной базе.
- Публичный сервер требует HTTPS, корректного AllowedHosts, секрет-хранилища,
  отдельной учётной записи SQL, внешних резервных копий и мониторинга.
- Локальная политика сеансов завершает авторизацию при перезапуске процесса;
  для нескольких серверных экземпляров понадобится отдельное решение.

## Границы реализации

- Выполнены внутренняя редактура и техническая проверка уроков, но нет
  независимой методической экспертизы всего курса преподавателем.
- Ведётся приблизительный учёт активного времени; длительность 10–15 минут
  требует проверки на реальных учащихся, а не только автоматических тестов.
- Озвучка сохранена в файлах, но синтезирована системным голосом, не записана
  профессиональным диктором. Необходима редакторская проверка единообразия акцента.
- Браузерное распознавание проверяет текст, а не качество произношения.
  Адаптер Azure Speech подготовлен, но ресурс не подключён и реальная
  акустическая оценка не подтверждена. Для него нужны `Speech:Key` и
  `Speech:Region` в секретах, интернет и согласие на передачу записи Microsoft.
- Полная автономность распознавания зависит от возможностей браузера.
- Проверка сигнатур медиа не заменяет антивирус или полное декодирование файлов.
- Независимый аудит безопасности и нагрузочные испытания публичного сервера
  не проводились. Локальные тесты не гарантируют отсутствие всех уязвимостей.
- Камера-переводчик, AR и свободный ИИ-диалог не входят в выбранный объём.

## Скрипты обслуживания

Папка `scripts` не нужна для обычной работы уже настроенного сайта.
Она содержит только инструменты установки, обслуживания и проверки проекта:

| Скрипт | Зачем нужен |
| --- | --- |
| `configure-mail.ps1` | Настроить SMTP в локальном хранилище секретов |
| `backup-database.ps1` | Создать и проверить резервную копию SQL Server |
| `reapply-deletions.ps1` | Повторить удаления аккаунтов после восстановления старой копии |
| `protect-local-secrets.ps1` | Ограничить доступ к локальным секретам и данным |
| `build-offline-audio.ps1` | Подготовить звуковые файлы для скачиваемого курса |
| `export-public-content.ps1` | Выгрузить только учебный контент для SQL seed |
| `export-learning-content.ps1` | Обновить учебные данные модульных тестов |
| `verify-public-database.ps1` | Проверить установку на временной базе |

## Публикация

Исходники, тесты, публичная SQL-схема и учебные данные входят в Git.
User Secrets, `App_Data`, локальные аккаунты, бэкапы, результаты тестов,
пользовательские загрузки, `bin`, `obj` и `node_modules` не публикуются.
Не загружайте приватный SQL-дамп или ZIP рабочей папки вместо исходников.
Локальная чистая копия не содержит данных пользователей.

Перед публикацией выполните сборку и модульные тесты. API, браузерные и
SQL-проверки запускаются на отдельном тестовом стенде. Не используйте
рабочие аккаунты и базу для тестов, изменяющих данные.

Лицензии сторонних библиотек сохранены в `wwwroot/lib`; сведения о фонетических
данных — в `wwwroot/PHONETICS_LICENSE.txt`. Лицензия на собственный код проекта
пока не выбрана; публичная публикация сама по себе не назначает открытую лицензию.
